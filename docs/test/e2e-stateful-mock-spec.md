# E2E 스펙 — 상태있는 목(B1) 영속성 단언

> 작성: 2026-07-02 · 대상: 목 BE 상태화 · 방식: SDD. 병렬 실행 하 상태 격리가 핵심 설계라 복잡 항목으로 분류.

## Context / 목표

현재 성공경로 스모크(글/댓글 작성·프로필 수정·알림 읽음)는 **무상태 목**이라 "요청이 200을 받는다"만 검증하고, **결과가 목록/상태에 반영되는지**는 단언하지 못한다. B1은 목에 상태를 도입해 이를 "진짜 영속성 단언"으로 격상한다.

## Current State (검증됨)

- `playwright.config.ts`: `fullyParallel: true` + 3개 브라우저 프로젝트(chromium·firefox·webkit).
- 목 BE(`e2e/mock-be/server.ts`)는 **단일 node 프로세스(:3099), 무상태** — 매 요청 고정 시드 반환.
- 인증 픽스처 `loginAs`/`loginAsOwner`는 **고정 토큰**(`E2E_SESSION_TOKEN`/`E2E_OWNER_TOKEN`) 주입.

## 핵심 난제 — 병렬 하 상태 오염

단일 공유 목에 전역 상태를 두면, **병렬로 도는 여러 테스트(+3개 브라우저가 같은 스펙을 동시 실행)**가 서로의 상태를 본다:
- append(글/댓글): 다른 테스트가 만든 글이 내 목록에도 보임 → "정확히 N개" 단언은 깨지지만 "내 글이 보인다"(존재) 단언은 안전.
- 단일값 변경(프로필 이름): 병렬 쓰기 → last-write-wins 레이스 → flaky.
- 알림 읽음: 같은 알림 ID를 여러 브라우저가 동시에 읽음 처리 → "미읽음 전제"가 깨져 flaky.

즉 **단일값 변경·초기상태 전제가 있는 케이스는 격리가 필수**다.

## 설계 옵션

### A) 토큰 스코프 인메모리 상태 (권장·풀 B1)
- `loginAs`/`loginAsOwner`가 **호출마다 유니크 토큰**(`${BASE}-${uuid}`) 주입. 역할 판별은 기존 `.includes(BASE)` 유지.
- 목 BE는 `Map<token, Bucket>`으로 상태 보관. Bucket은 최초 접근 시 시드로 lazy-init, 이후 뮤테이션은 해당 버킷에만 적용. GET은 버킷에서 읽음.
- 결과: **테스트별 완전 격리** → 3브라우저 병렬에도 결정론적. 글/댓글·프로필·알림 읽음 전부 커버.
- 비용: 중~높. **모든 인증 테스트가 쓰는 `loginAs`를 변경**(기존 그린 스위트 회귀 위험) + 목 BE에 상태 레이어.

### B) append-only + 존재 단언 (부분·저비용)
- 격리 없이 전역 append 리스트만. 각 테스트가 **유니크 콘텐츠**로 글/댓글 작성 후 "목록에 내 콘텐츠가 보인다"(존재)만 단언(정확한 개수·부재는 단언 안 함).
- 커버: 게시판 글/댓글 영속성만. 프로필·알림은 격리가 필요해 **제외**(스모크 유지).
- 비용: 낮음. 리스크: 낮음(존재 단언은 병렬 안전).

### C) 디스코프 (하지 않음)
- 스모크 + drift 게이트로 충분하다고 보고 B1을 백로그로만 남김. 3브라우저 병렬로 flaky 표면적이 커진 지금, 영속성의 증분 가치 대비 비용/리스크가 낮다는 판단.

## 결정 — B (append 게시판 영속성) 채택

- 가장 대표적인 영속성 케이스(글/댓글→목록 반영)를 잡으면서 append+존재 단언이라 3브라우저 병렬에 구조적으로 안전.
- 공유 `loginAs`를 건드리지 않아 84×3 그린 스위트에 회귀 리스크 없음.
- A의 추가 커버(프로필·알림 영속성)는 가치 대비 비용/리스크(전 인증 테스트가 쓰는 loginAs 변경)가 과함 → **후속(A)로 분리**.
- (참고) C도 방어 가능하나 사용자가 B1을 요청 → 저리스크 B로 실질 성과.

## Acceptance Criteria (옵션 A 기준)

1. 글 작성 후 같은 테스트에서 목록에 그 글이 보인다(존재).
2. 이름 수정 후 재조회 시 수정된 이름이 반영된다.
3. 알림 단건 읽음 후 그 알림이 읽음 상태로 바뀐다(미읽음 표식 사라짐).
4. 3개 브라우저 전체 + `e2e:burn` 무 flaky. typecheck 통과. 기존 스위트 회귀 없음.

## Out of scope
- 서버 재시작 간 영속(테스트 런 내 인메모리로 충분), 페이지네이션·정렬 정확성.
