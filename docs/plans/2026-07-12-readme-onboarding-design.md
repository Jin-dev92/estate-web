# README 온보딩 개편 설계

## 목적

새 개발자가 저장소를 처음 열었을 때 프로젝트의 역할, 실행 조건, 환경변수, 검증 명령, 주요 디렉터리를 README만으로 파악할 수 있게 한다.

## 변경 범위

- 기존 프로젝트 소개, 디자인 시스템, 마일스톤, E2E 현황은 유지한다.
- 최근 구현된 게시글 좋아요 기능을 기능 현황에 반영한다.
- Node.js와 pnpm 요구사항, 백엔드 연동 조건을 명시한다.
- `BACKEND_URL`, `NEXT_PUBLIC_WS_URL`, `NEXT_PUBLIC_KAKAO_CLIENT_ID`의 용도와 예시를 추가한다.
- 개발, 빌드, lint, 단위 테스트, 타입 검사, E2E 명령을 정리한다.
- 초기 placeholder 수준인 구조 설명을 실제 디렉터리 구조로 교체한다.
- 브라우저, Next.js Route Handler, 백엔드 사이의 호출 경계와 환경변수 노출 범위를 설명한다.
- 중복된 E2E 설명은 줄이되 커버리지와 남은 백로그는 보존한다.

## 비범위

- 애플리케이션 코드, 테스트 코드, 설정 파일은 변경하지 않는다.
- 새로운 기능이나 개발 도구를 추가하지 않는다.
- 백엔드 저장소의 문서는 수정하지 않는다.

## 성공 기준

1. README의 명령과 환경변수 이름이 현재 코드 및 `package.json`과 일치한다.
2. README의 구조 설명이 현재 주요 디렉터리와 역할을 반영한다.
3. 민감한 서버 환경변수와 공개 클라이언트 환경변수의 차이가 명확하다.
4. Markdown 링크와 코드 블록에 명백한 오류가 없다.
